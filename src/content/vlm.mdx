A vision-language model (VLM) is a language model that can also read images. Ask it what is on the table in a photograph and it answers in text; ask it to solve the geometry problem in a scanned worksheet and it writes out a solution. From the point of view of reinforcement learning, almost nothing about the setup of Sections 4 and 5 changes: the policy is still a distribution over token sequences, the reward is still a function of a prompt and a response, and PPO, DPO and GRPO all apply verbatim. The only difference is that the prompt now contains an image.

That one difference matters a great deal, because it introduces a failure mode that text-only models do not have in the same form. A VLM can produce a fluent, plausible and confident answer that is simply not about the image in front of it: it describes a fork that is not on the table, reads a number that is not on the sign, or counts five apples when there are four. This section is about how RL is used to fix that, how rewards can be made to actually check the image, and the open question of whether a model that reasons at length in text is still looking at the picture.

## The VLM as a policy

The dominant architecture, popularized by LLaVA (Liu et al., 2023), has three parts:

1. a **vision encoder**, typically a pretrained vision transformer, which maps an image $v$ to a sequence of patch features;
2. a **projector**, a small network (originally a linear map, later a two-layer MLP) that maps each patch feature into the embedding space of the language model, producing a sequence of **image tokens**;
3. a pretrained **language model**, which receives the image tokens interleaved with the text tokens of the question $q$ and generates the response autoregressively.

Training usually proceeds in stages: first the projector is fit on image–caption pairs so that image tokens land somewhere sensible in embedding space, then the projector and language model are fine-tuned on visual instruction data (questions about images with reference answers). RL comes after that, exactly as in the text-only pipeline.

<Definition name="VLM policy">
Let the prompt be $x = (v, q)$, an image $v$ together with a text query $q$. A **VLM policy** is an autoregressive distribution over responses $y = (y_1, \dots, y_T)$,
$$
\pi_\theta(y \mid v, q) = \prod_{t=1}^{T} \pi_\theta(y_t \mid v, q, y_{<t}),
$$
where the image enters only through the image tokens produced by the encoder and projector. As in Section 4, the token-level MDP has state $s_t = (x, y_{<t})$, action $y_t$, deterministic transitions, and a sequence-level reward $r(x, y)$ delivered at the end.
</Definition>

With $x = (v, q)$ every objective of Sections 4 and 5 carries over unchanged. The KL-regularized objective is
$$
J(\theta) = \mathbb{E}_{x \sim \mathcal{D}}\, \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)} \big[ r(x, y) \big] - \beta\, \mathbb{E}_{x \sim \mathcal{D}} \big[ \mathrm{KL}\big( \pi_\theta(\cdot \mid x) \,\|\, \pi_{\mathrm{ref}}(\cdot \mid x) \big) \big],
$$
DPO is the same loss on triples $(x, y_w, y_l)$, and GRPO samples $K$ responses $y^{(1)}, \dots, y^{(K)}$ per image–question pair. In practice the vision encoder is often frozen during RL and only the projector and language model are updated, which saves memory and avoids degrading features the model was pretrained to produce; whether RL should touch the encoder at all is a design choice without a settled answer.

So the machinery is not new. What is new is the content of the reward: what it has to check, and how easily a policy can satisfy it without using the image.

## What changes with images

### Hallucination

<Definition name="Visual hallucination">
A response $y$ to $(v, q)$ contains a **visual hallucination** if it asserts something about $v$ that is false: an object that is absent (**object hallucination**), a wrong attribute such as colour, count or text, or a wrong relation such as position or action.
</Definition>

Hallucination in a VLM is more sharply defined than in a text-only model, because the image is a fixed, checkable source of truth. A caption that mentions a dog in a picture of an empty park is wrong regardless of how plausible dogs in parks are. Standard evaluations exploit this: some compare the objects mentioned in a caption against annotated object lists, others ask a battery of yes/no questions of the form "Is there a $\ldots$ in the image?" and check the answers.

### The language prior

A useful way to think about the source of hallucination is to compare the VLM with the same model run without the image. Write $\pi_\theta(y \mid q)$ for the distribution the language model would assign with the image tokens removed (or replaced by uninformative ones). Then
$$
\log \pi_\theta(y \mid v, q) = \log \pi_\theta(y \mid q) + \log \frac{\pi_\theta(y \mid v, q)}{\pi_\theta(y \mid q)}.
$$
The first term is the **language prior**: what is likely to be said in response to $q$ in general. The second is the evidence the image contributes. The language model was pretrained on vastly more text than the multimodal stages show it images, so the first term is sharp and confident, while the second is comparatively weak. When the two disagree — a kitchen scene in which, unusually, there is no refrigerator — the prior often wins, and the model mentions a refrigerator. Hallucinations also become more frequent later in long responses, as the generated text itself increasingly conditions what comes next and the image tokens recede in relative influence.

### Rewards must look at the image

The consequence for RL is direct. A reward model that judges responses mostly on fluency, helpfulness and detail — the qualities a text-only reward model of Section 4 learns to reward — will happily reward detailed hallucinations, since a more detailed description contains more claims and so more chances to be wrong. Reward hacking of exactly the kind described in Section 4 appears in a specific form: the policy learns to write longer, richer, more confident descriptions, and the fraction of false claims rises. Every method in the rest of this section is, in one way or another, an attempt to make the reward depend on whether the response is true of $v$.

## Preference learning against hallucination

### Factually augmented RLHF

An early and influential application of RLHF to an open VLM was LLaVA-RLHF (Sun et al., 2023). Human annotators compared pairs of responses with an emphasis on hallucination, a reward model was trained on these comparisons, and the policy was optimized with PPO under a KL penalty, all as in Section 4.

The key observation was that the reward model, itself a VLM, is vulnerable to the same language prior as the policy, so it may fail to notice a hallucination that a human would catch. **Factually augmented RLHF** addresses this by giving the reward model extra ground-truth information that the policy does not see: for example, human-written captions of the image, or the correct option for a multiple-choice question. Formally, the reward is $r_\phi(v, q, y; c)$ with side information $c$ about $v$, while the policy remains $\pi_\theta(y \mid v, q)$. Because the reward model can check claims against text it reads reliably, rather than against an image it may misperceive, its judgement of factuality improves, and the policy is pushed towards responses consistent with the side information. The asymmetry is legitimate because the side information is only needed at training time.

### Fine-grained corrections

Response-level preferences are a blunt signal for hallucination. A long description may be correct in nine sentences and wrong in one, and a pairwise label only says which whole response is better. RLHF-V (Yu et al., 2024) instead collects **correctional feedback**: annotators take a model response and minimally edit the hallucinated segments into correct ones. The edited response is $y_w$, the original is $y_l$, and the two differ only in the corrected segments.

This pairing has two benefits. First, the preference signal is attributable: the difference between $y_w$ and $y_l$ is exactly the hallucination, not a mixture of style, length and content. Second, it invites a dense variant of DPO. Writing $\log \pi_\theta(y \mid x) = \sum_t \log \pi_\theta(y_t \mid x, y_{<t})$ and splitting the tokens of each response into unchanged tokens $U$ and corrected tokens $C$, one can reweight the log-likelihood as
$$
\log \tilde\pi_\theta(y \mid x) = \sum_{t \in U} \log \pi_\theta(y_t \mid x, y_{<t}) + \gamma_C \sum_{t \in C} \log \pi_\theta(y_t \mid x, y_{<t}), \qquad \gamma_C > 1,
$$
and use $\tilde\pi_\theta$ in place of $\pi_\theta$ inside the DPO loss, so that the gradient concentrates on the tokens that were actually wrong. (RLHF-V's dense DPO works in this spirit; the exact normalization of the two sums is a detail of the method.) Here $\gamma_C$ is a weight, not a discount factor.

### AI feedback

Human correction is expensive. RLAIF-V (Yu et al., 2024) replaces it with feedback from open-source VLMs, using a **divide-and-conquer** scheme: each candidate response is split into atomic claims, each claim is turned into a simple verification question about the image, and a labeller model answers those questions. A response's score is then determined by the number of claims judged false, and preference pairs are formed from responses to the same prompt with different scores. The underlying point is general: checking a single short claim against an image is much easier, for humans and models alike, than judging a whole paragraph, so decomposing the response makes AI feedback more reliable than asking a judge for a holistic preference.

### Constructing hallucinated negatives

Another route to preference data avoids judging free-form responses altogether. Start from a correct response $y_w$, for instance a ground-truth caption, and produce $y_l$ by **injecting hallucinations**: replace an object with a plausible co-occurring one that is absent, change a colour or a count, swap left and right. The pair $(y_w, y_l)$ is then guaranteed to differ only in a hallucination, and the hallucinations it contains are exactly the ones the language prior makes likely, since they were chosen for plausibility. A related trick generates $y_l$ by running the model itself on a corrupted or noised version of the image, which produces responses dominated by the language prior. Both ideas make the preference signal concentrated and cheap, at the cost of a distribution shift: injected errors may not resemble the errors the policy actually makes.

## When preference optimization ignores the image

There is a structural problem with applying DPO to VLMs, observed by several groups and studied in particular under the name mDPO (conditional preference optimization). In a standard multimodal preference pair, both responses are conditioned on the same image. The question is whether the DPO objective forces the model to use that image at all.

Write the DPO implicit reward from Section 4 as
$$
h_\theta(v, q, y) = \log \frac{\pi_\theta(y \mid v, q)}{\pi_{\mathrm{ref}}(y \mid v, q)},
$$
so that the loss on a triple is $-\log \sigma\big(\beta\,[h_\theta(v, q, y_w) - h_\theta(v, q, y_l)]\big)$. The image appears in both terms, and the loss only rewards the margin between them.

<Result name="Response-only pairs do not require image use">
Suppose that in the preference data the label is predictable from $(q, y_w, y_l)$ alone, for example because chosen responses are systematically shorter, more hedged or written in a recognizable style. Then the DPO loss can be driven down by a policy whose change from the reference ignores the image. Conversely, consider an image-contrastive pair: one response $y$ and two images, the true image $v$ and a corrupted image $v'$ (cropped, masked or replaced), with preference for $y$ under $v$. Its margin is
$$
h_\theta(v, q, y) - h_\theta(v', q, y) = \log \frac{\pi_\theta(y \mid v, q)}{\pi_\theta(y \mid v', q)} - \log \frac{\pi_{\mathrm{ref}}(y \mid v, q)}{\pi_{\mathrm{ref}}(y \mid v', q)} .
$$
If $\pi_\theta$ is image-blind, meaning $\pi_\theta(y \mid v, q) = \pi_\theta(y \mid v', q)$, the first term vanishes and the margin equals a constant that does not depend on $\theta$. An image-blind policy therefore cannot reduce the loss on image-contrastive pairs at all; the only way to increase the margin is to make $\pi_\theta(y \mid v, q)$ larger relative to $\pi_\theta(y \mid v', q)$, that is, to make the response depend on the image.
</Result>

The first half of the statement is an existence claim rather than a theorem about what training will do: gradient descent may or may not find an image-blind solution. But it shows that nothing in the response-contrastive objective rules one out, and it has been reported that DPO on standard multimodal pairs can give similar results whether or not the image is shown during training. The second half is exact. It explains the idea of **conditional preference optimization**: alongside the usual pairs $(v, q, y_w, y_l)$, add pairs that hold the response fixed and contrast images, so that the preference is conditional on the visual input and the image's influence no longer cancels.

A second issue is that DPO only constrains differences, so the likelihood of the chosen response can fall during training as long as the rejected one falls faster. In VLMs this is particularly harmful, since a model that lowers the probability of correct descriptions as well as wrong ones has not learned to describe the image. Adding an anchor term that pushes the implicit reward of the chosen response above a threshold, such as $-\log \sigma\big(\beta\, h_\theta(v, q, y_w) - \delta\big)$ for a margin $\delta \ge 0$, is a common remedy.

## Verifiable rewards for perception

Section 5 showed that when a correct answer can be checked by a program, a learned reward model can be replaced by a checker, removing a large source of reward hacking. Many visual tasks have exactly this property, and in 2025 a wave of work applied R1-style RL (GRPO with rule-based rewards, a reasoning trace followed by a final answer) to VLMs.

### Rule-based rewards

The common verifiable rewards for vision are:

- **Grounding.** The model outputs a bounding box $\hat b$ for a referred object, with ground truth $b$. The reward is the **intersection over union**
$$
r(x, y) = \mathrm{IoU}(\hat b, b) = \frac{|\hat b \cap b|}{|\hat b \cup b|} \in [0, 1],
$$
or its thresholded version $\mathbf{1}[\mathrm{IoU}(\hat b, b) \ge \tau]$. IoU is a dense reward: a box that is close but not exact still earns partial credit, which gives GRPO useful variation among the $K$ samples. For detection with several objects, predicted and true boxes are matched (for example by a maximum-weight bipartite matching on IoU) and the matched IoUs are averaged, with penalties for unmatched predictions.
- **Counting.** The reward is $\mathbf{1}[\hat n = n]$, or a smoothed version that decreases with $|\hat n - n|$.
- **OCR.** Exact match, or one minus a normalized edit distance between the predicted and reference strings.
- **Multiple-choice and short-answer VQA.** Exact match of the extracted answer, after normalization.
- **Visual mathematics.** Geometry problems, function plots, charts and tables, where the answer is a number or expression checked as in Section 5.

These are usually combined with a **format reward**, an indicator that the response follows the required template — a reasoning segment followed by an answer segment in designated tags such as `<think>` and `<answer>`, with the answer parseable (a box given as four coordinates, a number, a single option letter). The total reward is typically a sum $r = r_{\mathrm{task}} + \lambda\, r_{\mathrm{format}}$. The format reward is necessary because the task reward can only be computed on parseable outputs, but it is also the easiest component to hack, and once the policy reliably follows the format it carries no further signal.

Examples include Visual-RFT, which applied verifiable rewards including IoU to detection and classification, and VLM-R1, which focused on referring-expression grounding. A recurring observation in this line of work is that RL with such rewards generalizes better out of domain than supervised fine-tuning on the same data, mirroring the corresponding finding for text in Section 5; how robust this observation is across tasks and model scales is still being established.

<Example name="GRPO for grounding">
Take a prompt $x = (v, q)$ with $q$ = "Give the bounding box of the mug to the left of the laptop", and sample $K$ responses. Each response is parsed into a box $\hat b^{(k)}$; unparseable responses receive reward $0$. With rewards $r^{(k)} = \mathrm{IoU}(\hat b^{(k)}, b)$, the group-relative advantage of Section 5 is
$$
\hat A^{(k)} = \frac{r^{(k)} - \bar r}{\mathrm{std}(r^{(1)}, \dots, r^{(K)})}, \qquad \bar r = \frac{1}{K} \sum_{j=1}^{K} r^{(j)},
$$
assigned to every token of response $k$. A response that picks the mug on the right gets IoU near $0$ and negative advantage; one that picks the correct mug but draws a loose box gets a moderate positive advantage; the tightest box gets the largest. The signal thus teaches both which object the phrase refers to and how to localize it, without any reward model.
</Example>

### Where verifiable rewards fall short

Rule-based rewards check the final answer, not the path. A model can answer a counting question correctly while its reasoning describes the wrong objects, or answer a multiple-choice question correctly by exploiting priors in how the options are written, without looking at the image. Multiple-choice VQA is particularly exposed: if a fraction of questions can be answered from the text alone, RL on those questions reinforces the language prior rather than perception. Curating data so that answers genuinely require the image, for instance by discarding questions a text-only model answers correctly, is an important and somewhat underappreciated part of making these rewards meaningful.

## Thinking with images

A text reasoning trace has a limitation specific to vision: the image is encoded once, at a fixed resolution, at the start of the prompt. If the relevant detail is small — a street sign in the background, a digit on a meter — the model may simply not have it in its image tokens, and no amount of textual reasoning will recover it. **Thinking with images** (a phrase popularized by OpenAI's o3 in 2025) refers to models that can act on the image during reasoning: crop a region, zoom in, rotate, draw an auxiliary line, and then look again.

This turns single-turn generation into a multi-turn decision process. The action space contains ordinary tokens and also **visual tool calls** such as $\mathrm{crop}(b)$ for a box $b$. When the policy emits a tool call, the environment executes it and appends the resulting image, encoded into fresh image tokens, to the context. Writing $o_j$ for the $j$-th tool observation, a trajectory is
$$
\tau = (x, y^{1}, o_1, y^{2}, o_2, \dots, y^{m}),
$$
where each $y^{i}$ is a segment of policy-generated tokens ending in a tool call or the final answer. The policy gradient of Section 3 applies to the policy's own actions only. Since the observations are produced by the environment rather than sampled from $\pi_\theta$, their log-probabilities do not appear in $\log p_\theta(\tau)$, and in practice the observation tokens are masked out of the loss:
$$
\nabla_\theta J(\theta) = \mathbb{E}_\tau \Big[ \sum_{i=1}^{m} \sum_{t} \nabla_\theta \log \pi_\theta\big(y^{i}_t \mid x, y^{1}, o_1, \dots, o_{i-1}, y^{i}_{<t}\big)\, \hat A^{i}_t \Big].
$$
The reward is usually the outcome reward of the final answer, possibly with small terms for well-formed tool calls. An appealing feature of this setup is that the decision of where to look is learned from outcome reward alone: crops that lead to correct answers are reinforced. Systems trained this way can learn when zooming helps without being told, but the design space (which tools, how to reward tool use without encouraging gratuitous calls, how to prevent the policy from collapsing to never using tools) is wide open.

This is the same structure as the agentic, multi-turn RL used for text models with code interpreters or search, with the difference that the observations are images. The extension to **GUI and computer-use agents** is immediate: the state is a screenshot, the actions are clicks, typing and scrolling at screen coordinates, and the reward is task completion, checked by inspecting the final state of the application or web page. Grounding rewards of the IoU type reappear here, since predicting where to click is a localization problem. Long horizons, sparse rewards and the cost of running real environments make this one of the hardest settings in the area.

## Perception versus reasoning

A textual chain of thought is a long sequence of tokens generated after the image tokens. As it grows, two things happen. The model's own previous tokens make up an increasing share of its context, and if an early step misreads the image, later steps reason correctly from a false premise. It has been reported that long reasoning traces in VLMs can **drift away from visual evidence**: the model's attention to image tokens decreases, and hallucination rates rise with trace length, so that a model trained for longer reasoning can become worse at simple perception questions even as its accuracy on maths-heavy visual tasks improves.

This raises a basic question about what RL is doing. A visual question can fail for two different reasons: the model mis-perceives the image (reads the wrong value off a chart), or it perceives correctly but reasons badly (adds the values wrong). Outcome rewards cannot distinguish the two. Formally, if we imagine an intermediate perceptual description $z$ of the image,
$$
\pi_\theta(y \mid v, q) = \sum_{z} \pi_\theta(z \mid v, q)\, \pi_\theta(y \mid z, q),
$$
then an outcome reward that improves $\mathbb{E}[r]$ may do so by improving either factor. On benchmarks dominated by mathematical reasoning over clear diagrams, most of the gain may come from the second factor, which is essentially the text reasoning of Section 5. Whether RL with outcome rewards substantially improves the first factor — the model's ability to see — or mostly improves reasoning on top of fixed perception is, as of this writing, an open question, and the evidence is mixed. It is closely related to the question raised in Section 5 of whether RL adds capabilities or mostly sharpens ones the base model already had.

Several remedies have been proposed: rewards for the accuracy of an explicit perception step (a description of the image checked against annotations), consistency rewards that compare reasoning with and without the image, tools that re-encode image regions so that perception can be refreshed mid-reasoning, and simply keeping reasoning short when the task is perceptual.

## Reward models for multimodal outputs

Not every visual task has a checker. Open-ended description, visual dialogue and helpfulness still require a learned reward. Two forms are common:

- **Scalar reward models** trained with the Bradley–Terry loss of Section 4, with a VLM backbone so that $r_\phi(v, q, y)$ can read the image.
- **Generative judges**: a VLM prompted (and often fine-tuned) to write a critique of the response against the image and then output a score or a preference. Generative judges can decompose a response into claims and check each one, as in the divide-and-conquer scheme above, and their reasoning can be inspected.

Both inherit the weakness that motivated this section: a multimodal judge can itself hallucinate, and it may be biased towards responses that resemble its own outputs. Factual augmentation with side information, claim-level decomposition, and mixing learned rewards with verifiable ones where possible are the main defences. The following table summarizes the reward types discussed.

| Reward type | Source | What it checks | Main weakness |
| --- | --- | --- | --- |
| Human preference | Annotator comparisons or corrections | Overall quality; with corrections, specific hallucinated segments | Expensive; response-level labels mix style and truth |
| AI preference | VLM judge, often claim by claim | Factual consistency of individual claims with the image | Judge shares the policy's blind spots |
| Factually augmented RM | Learned RM given captions or answers | Consistency with ground-truth side information | Limited by the coverage of the side information |
| Rule-based | Program comparing to an annotation | IoU of boxes, counts, strings, option letters, numbers | Checks only the final answer; data may be answerable without the image |
| Tool or environment outcome | Executing the trajectory | Whether a multi-step task (zoom-and-answer, GUI task) succeeded | Sparse; costly environments; credit assignment over many steps |

## Open problems

- **Does RL improve seeing?** Separating gains in perception from gains in reasoning, and designing rewards that target perception directly, remains unresolved.
- **Image-conditional preferences.** Response-contrastive DPO can underuse the image. How best to construct image-contrastive pairs (which corruptions, how many) and how to combine them with ordinary pairs is not settled.
- **Process rewards for visual reasoning.** Checking whether each intermediate claim about the image is true would give denser and more faithful signal than outcome rewards, but needs either dense annotation or a reliable verifier.
- **Tool use and active perception.** Which visual operations to expose, how to reward their use without encouraging gratuitous calls, and how to scale multi-turn RL with image observations efficiently.
- **Faithfulness of long reasoning.** Keeping long chains of thought tied to visual evidence, rather than drifting into text-only reasoning, is an active topic with no standard solution.
- **Data contamination by the language prior.** Benchmarks and RL datasets in which questions can be answered from text alone overstate visual ability and can reinforce the prior during training.
